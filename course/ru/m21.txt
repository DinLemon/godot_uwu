# MODULE m21 | Отладка и экспорт | Искать ошибки и выпускать игру

## LESSON m21-1 | Как искать ошибку | 8
:: goals
- План действий, когда что-то не работает
- Отладочный `print`

:: text Спокойный план
visual: concept-m21
Игра ведёт себя не так. Это нормально. Иди по шагам:

1. **Прочитай ошибку.** Панель **Debugger → Errors** внизу. Там текст и номер строки. Двойной клик — переход к строке.
2. **Опиши словами**, что ожидал и что видишь. «Ждал прыжка — персонаж стоит».
3. **Проверь самое простое**: сохранён ли скрипт, прикреплён ли он к нужному узлу, подключён ли сигнал, правильное ли имя узла.
4. **Добавь print** и посмотри, доходит ли код до нужного места и что лежит в переменных.
5. **Меняй одну вещь за раз** и проверяй.

> Помогает метод «резиновой уточки»: объясни код вслух строчка за строчкой — кому угодно, хоть игрушке. Ошибка часто находится на середине объяснения.

:: code
Отладочный print показывает, что происходит внутри. Здесь прыжок не срабатывает. Запусти и найди причину по выводу.
```gd
extends CharacterBody2D
# тренажёр: кадров=2 нажато=jump

func _physics_process(delta):
	print("кадр, на полу: ", is_on_floor())
	if Input.is_action_just_pressed("jump") and is_on_floor():
		print("прыжок!")
		velocity.y = -400
	move_and_slide()
```
```out
кадр, на полу: false
кадр, на полу: false
```
Вывод показывает: `is_on_floor()` всё время `false` — пола нет. В тренажёре добавь в первую строку `пол=0`. В Godot это значило бы: нет StaticBody2D под ногами или у него нет CollisionShape2D.

:: text print_debug и push_warning
- `print_debug(x)` — как print, но в Godot добавляет, из какого файла и строки напечатано.
- `push_warning("текст")` — жёлтое предупреждение в панели Debugger.
- `push_error("текст")` — красная ошибка в Debugger, но игра продолжает работать.
- `assert(условие, "текст")` — если условие ложно, игра остановится на этой строке. Только в редакторе: в готовой игре `assert` пропускается.

:: code
`assert` помогает ловить «невозможные» ситуации.
```gd
extends Node

func _ready():
	set_health(50)
	set_health(-10)

func set_health(value):
	assert(value >= 0, "здоровье не может быть меньше нуля")
	print("здоровье = ", value)
```
fails: yes
Первый вызов прошёл, второй остановил программу. Godot покажет строку с `assert` и твоё сообщение.

:: quiz
Код в `_on_coin_body_entered` не выполняется. Что проверить первым?
[x] Подключён ли сигнал (есть ли зелёная иконка у функции) => Верно. Очень частая причина.
[ ] Переустановить Godot => С Godot всё в порядке. Начинай с простых проверок.
[ ] Переписать игру заново => Слишком радикально. Сначала — print и проверка сигнала.

:: recap
- План: прочитать ошибку → описать словами → проверить простое → print → одна правка за раз.
- `print`, `print_debug`, `push_warning`, `push_error`, `assert`.

## LESSON m21-2 | Отладчик: точки останова | 7
:: goals
- Как остановить игру на строке
- Как посмотреть значения переменных

:: steps Точка останова
visual: guide-m21-2-0
Открой скрипт игрока.
- Кликни слева от номера строки с `move_and_slide()`. Появится красная точка — **breakpoint** (точка останова).
- Запусти `F6`. Игра остановится, когда дойдёт до этой строки. Строка подсветится.
- Внизу откроется **Debugger → Stack Trace**. Справа видны все переменные: `velocity`, `position`, `delta`.
- `F10` — выполнить одну строку (**Step Over**). `F11` — зайти внутрь функции (**Step Into**).
- `F12` или кнопка **Continue** — продолжить до следующей остановки.
- Кликни по красной точке ещё раз — она исчезнет.

:: text Remote: дерево работающей игры
Пока игра запущена, в панели **Scene** вверху появляются вкладки **Remote** и **Local**.

**Remote** показывает дерево **живой** игры: какие узлы есть прямо сейчас и какие у них значения. Можно кликнуть узел и посмотреть свойства в Инспекторе.

Удобно, чтобы проверить: удалилась ли пуля? Создались ли враги? Какая у игрока позиция?

:: text Видимые формы
**Debug → Visible Collision Shapes** — при запуске формы столкновений будут видны. Сразу понятно, почему персонаж «цепляется» за воздух: форма больше картинки.

:: quiz
Ты хочешь узнать, удаляются ли пули после вылета за экран. Где смотреть?
[x] Вкладка Remote в панели Scene, пока игра запущена => Верно. Там видно живое дерево.
[ ] Вкладка Local => Это сцена в редакторе, а не в игре.
[ ] Панель FileSystem => Там файлы, а не узлы игры.

:: recap
- Красная точка слева от строки — **breakpoint**. `F10` — шаг, `F12` — продолжить.
- **Remote** — дерево работающей игры.
- **Debug → Visible Collision Shapes** — видеть формы.

## LESSON m21-3 | Экспорт на компьютер | 8
:: goals
- Что такое экспорт
- Как собрать игру в .exe

:: text Экспорт — сборка игры
**Экспорт** — превращение проекта в готовую игру, которую можно запустить **без Godot**.

Для экспорта нужны **шаблоны экспорта** (export templates). Это «движок без редактора» под каждую систему. Скачиваются один раз.

:: steps Шаблоны экспорта
visual: guide-m21-3-0
- Открой **Project → Export…** (Проект → Экспорт).
- Если внизу красная надпись про отсутствие шаблонов, нажми **Manage Export Templates**.
- Нажми **Download and Install**. Это около 1 ГБ — подожди.

:: steps Сборка для Windows
visual: guide-m21-3-1
- В окне **Export** нажми **Add…** → **Windows Desktop**.
- В **Export Path** выбери папку **вне** проекта, например `Документы/my_game_build/my_game.exe`.
- Нажми **Export Project**. Галочку **Export With Debug** сними — так игра будет чище.
- Открой папку: там `my_game.exe` (и, возможно, `.pck` с данными). Это и есть игра. Её можно запаковать в zip и отправить другу.

!> Не экспортируй игру внутрь папки проекта: Godot начнёт видеть свои же файлы сборки.

:: quiz
Зачем нужны шаблоны экспорта?
[x] Это движок без редактора под каждую систему — из них собирается игра => Верно.
[ ] Это готовые игры-примеры => Нет, примеры — в AssetLib и демо-проектах.
[ ] Без них не работает редактор => Редактор работает и без них. Они нужны только для экспорта.

:: recap
- Экспорт: **Project → Export**.
- Один раз скачать шаблоны: **Manage Export Templates → Download and Install**.
- Пресет **Windows Desktop** → **Export Project** → папка вне проекта.

## LESSON m21-4 | Игра в браузере и itch.io | 8
:: goals
- Как экспортировать игру для браузера
- Как выложить её на itch.io

:: text Web-экспорт
Godot умеет собирать игру для **браузера** (HTML5). Тогда в неё можно играть по ссылке, без скачивания.

Требования:
- рендерер **Compatibility** (мы выбрали его в модуле 1);
- C# в веб-экспорте не поддерживается — но мы пишем на GDScript, всё в порядке.

:: steps Сборка для браузера
visual: guide-m21-4-0
- **Project → Export → Add… → Web**.
- **Export Path**: новая пустая папка, файл `index.html`. Например `Документы/my_game_web/index.html`.
- Нажми **Export Project**. В папке появятся `index.html`, `.js`, `.wasm`, `.pck`.
- Проверить можно прямо из редактора: кнопка с иконкой HTML5 справа вверху (**Remote Deploy**) запустит игру в браузере.

!> Если просто открыть `index.html` двойным кликом, игра может не запуститься: браузеры не дают сайтам с диска загружать файлы. Проверяй через кнопку в редакторе или выкладывай на сайт.

:: steps Публикация на itch.io
visual: guide-m21-4-1
[itch.io](https://itch.io) — бесплатная площадка для инди-игр.
- Зарегистрируйся и нажми **Upload new project**.
- **Kind of project**: **HTML**.
- Запакуй **содержимое** папки `my_game_web` в zip (не саму папку, а файлы внутри). Загрузи zip.
- Поставь галочку **This file will be played in the browser**.
- В **Embed options** укажи размер окна игры (например 1152 × 648 — размер по умолчанию в Godot).
- Включи **SharedArrayBuffer support**, если игра не запускается (это нужно некоторым сборкам).
- Сохрани. Сначала страница будет в режиме **Draft** (черновик) — посмотри, работает ли. Потом поменяй на **Public**.

:: quiz
Какой рендерер нужен для игры в браузере?
[ ] Forward+ => Он не работает в браузере.
[x] Compatibility => Верно.
[ ] Любой => Для Web нужен Compatibility.

:: recap
- Web-экспорт: пресет **Web**, рендерер **Compatibility**.
- Файлы не открывают двойным кликом — проверяют через кнопку в редакторе или на сайте.
- itch.io: проект типа **HTML**, zip с содержимым папки сборки.
