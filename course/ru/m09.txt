# MODULE m09 | Скрипт и узел | Как код управляет узлами в игре

## LESSON m09-1 | extends и свойства узла | 7
:: goals
- Что значит `extends`
- Как скрипт читает и меняет свойства своего узла

:: text Скрипт «продолжает» узел
`extends Node2D` значит: «этот скрипт — продолжение узла Node2D». Скрипт получает **все свойства и функции** этого узла и добавляет свои.

Поэтому внутри скрипта можно сразу писать `position`, `rotation`, `visible` — это свойства самого узла.

```gd
extends Node2D

func _ready():
	position = Vector2(100, 50)   # переставить узел
	rotation_degrees = 45         # повернуть на 45°
```

Скрипт с `extends Sprite2D` сможет менять картинку, с `extends Label` — текст.

:: code
В тренажёре тоже есть простые узлы. У любого узла есть свойство `name` — имя в дереве. У `Node2D` есть `position`.
```gd
extends Node2D

func _ready():
	print(name)
	print(position)
	position.x = 120
	position.y += 40
	print(position)
```
```out
Main
(0.0, 0.0)
(120.0, 40.0)
```
В тренажёре корневой узел всегда называется `Main`. `position` — это пара чисел x и y. Подробно разберём в модуле про 2D.

:: code
Если скрипт `extends Node`, у него нет позиции. Запусти.
```gd
extends Node

func _ready():
	position.x = 10
```
fails: yes
`Node` — самый простой узел, у него нет места на экране. Позиция появляется у `Node2D` и его наследников.

:: quiz
Скрипт начинается с `extends Label`. Что это значит?
[x] Скрипт можно прикрепить к узлу Label, и он может менять его свойства, например `text` => Верно.
[ ] Скрипт создаёт новый Label => Нет. Он управляет тем узлом, к которому прикреплён.
[ ] Скрипт работает только с текстом в коде => Нет, `extends` говорит о типе узла.

:: recap
- `extends Тип` — скрипт продолжает узел этого типа и получает все его свойства.
- Свойства своего узла пишутся прямо по имени: `position`, `visible`, `text`.

## LESSON m09-2 | _process и delta | 8
:: goals
- Что такое кадр
- Когда вызывается `_process`
- Зачем нужна `delta`

:: text Игра — это кадры
Игра показывает картинку не один раз, а **много раз в секунду**. Каждая картинка — **кадр**. Обычно 60 кадров в секунду.

Godot умеет вызывать функцию `_process(delta)` **каждый кадр**. Всё, что должно происходить постоянно, пишут туда: движение, проверка клавиш, таймеры.

- `_ready()` — один раз, при появлении узла.
- `_process(delta)` — каждый кадр, пока узел в игре.

:: text Что такое delta
`delta` — сколько секунд прошло с прошлого кадра. При 60 кадрах в секунду это примерно `0.016`.

Зачем: компьютеры разные. Один показывает 30 кадров, другой 144. Если двигать персонажа на 5 пикселей каждый кадр, на быстром компьютере он побежит в 5 раз быстрее.

Поэтому скорость умножают на `delta`:

```gd
var speed = 200   # пикселей в СЕКУНДУ

func _process(delta):
	position.x += speed * delta
```

Теперь за секунду узел пройдёт 200 пикселей на любом компьютере.

:: text Кадры в тренажёре
Тренажёр тоже умеет крутить кадры. Вверху примера может стоять строка-настройка:

```gd
# тренажёр: кадров=4 дельта=0.25
```

Это значит: «вызови `_process` 4 раза, каждый раз с `delta = 0.25`». Так числа получаются круглыми и их легко проверить.

В настоящем Godot такая строка — просто комментарий. Он ни на что не влияет.

:: code
За 4 кадра по 0.25 секунды прошла ровно 1 секунда. Узел должен проехать 100 пикселей.
```gd
extends Node2D
# тренажёр: кадров=4 дельта=0.25

var speed = 100

func _process(delta):
	position.x += speed * delta
	print(position.x)
```
```out
25.0
50.0
75.0
100.0
```
Поменяй скорость или число кадров и запусти снова.

:: quiz
Где писать код, который двигает персонажа всё время, пока идёт игра?
[ ] В `_ready()` => `_ready` выполнится один раз. Персонаж сдвинется один раз и встанет.
[x] В `_process(delta)` => Верно. Она вызывается каждый кадр.
[ ] В любом месте вне функций => Вне функций можно только объявлять переменные и функции.

:: quiz
Зачем умножать скорость на `delta`?
[x] Чтобы движение было одинаковым при любом количестве кадров в секунду => Верно.
[ ] Чтобы движение было плавным => Плавность даёт частота кадров. `delta` даёт одинаковую скорость.
[ ] Без `delta` будет ошибка => Ошибки не будет. Но скорость будет зависеть от компьютера.

:: task
Узел должен **вращаться** со скоростью 90 градусов в секунду. Свойство угла в градусах — `rotation_degrees`. За 4 кадра по 0.25 секунды он должен повернуться на 90°. Напечатай угол на каждом кадре:
```text
22.5
45.0
67.5
90.0
```
```gd
extends Node2D
# тренажёр: кадров=4 дельта=0.25

var turn_speed = 90

func _process(delta):
	pass
```
```solution
extends Node2D
# тренажёр: кадров=4 дельта=0.25

var turn_speed = 90

func _process(delta):
	rotation_degrees += turn_speed * delta
	print(rotation_degrees)
```
```expect
22.5
45.0
67.5
90.0
```
hint: По образцу движения: `rotation_degrees += turn_speed * delta`.
hint: Потом `print(rotation_degrees)`.

:: recap
- Игра — это кадры, обычно 60 в секунду.
- `_process(delta)` вызывается каждый кадр.
- `delta` — секунды с прошлого кадра. Скорость × `delta` = одинаково на любом компьютере.

## LESSON m09-3 | @export — настройка в Инспекторе | 6
:: goals
- Как показать переменную в Инспекторе
- Зачем это нужно

:: text Переменная в Инспекторе
visual: concept-m09
Если перед переменной написать `@export`, она появится в **Inspector** у узла. Её можно будет менять мышкой, не открывая код.

```gd
extends Node2D

@export var speed = 200
@export var max_health = 100
@export var player_name = "Герой"
```

Зачем: у одного скрипта врага может быть много копий. Одному врагу ставишь скорость 100, другому 300 — в Инспекторе. Код один.

!> Значение из Инспектора **побеждает** значение в коде. Поменял в коде `speed = 200` на 250, а в Инспекторе стоит 300 — будет 300.

:: steps Попробуй
visual: guide-m09-3-0
Открой проект и сцену `main.tscn`. У узла `Main` есть скрипт `main.gd`.
- Открой `main.gd` и под `extends Node2D` допиши строку: `@export var speed = 200`.
- Сохрани скрипт: `Ctrl+S`.
- Выбери узел `Main` в дереве. В Инспекторе появится поле **Speed** со значением 200.
- Поменяй его на 350. Рядом появится стрелочка «сбросить» — она возвращает значение из кода.

:: text Подсказки для Инспектора
У `@export` есть варианты:

```gd
@export_range(0, 500) var speed = 200       # ползунок от 0 до 500
@export_multiline var description = ""      # большое поле для текста
@export var color: Color = Color.WHITE       # палитра цветов
```

С указанным типом Инспектор показывает удобный редактор: для `Color` — палитру, для `bool` — галочку.

:: quiz
Ты написал `@export var jump = 400`, а в Инспекторе поставил 600. Какая сила прыжка будет в игре?
[ ] 400 => Значение из Инспектора побеждает значение по умолчанию из кода.
[x] 600 => Верно. Инспектор сохраняет своё значение в сцене.
[ ] 1000 => Значения не складываются.

:: recap
- `@export var x = 5` — переменная видна и меняется в Inspector.
- Значение из Инспектора важнее значения в коде.
- `@export_range(мин, макс)` — ползунок.

## LESSON m09-4 | Найти другой узел: $ и get_node | 8
:: goals
- Как скрипту добраться до другого узла
- Что такое путь к узлу
- Зачем `@onready`

:: text Путь к узлу
Скрипт прикреплён к одному узлу. Но часто нужно менять **соседей**: поменять текст в `Label`, спрятать `Sprite2D`.

Для этого есть `$` и путь к узлу:

```tree
Player          ← скрипт здесь
├── Sprite2D
└── HealthLabel
```

```gd
$Sprite2D.visible = false
$HealthLabel.text = "HP: 100"
```

`$Имя` — ребёнок с таким именем. `$Папа/Сын` — внук. `$"../Enemy"` — сосед (`..` значит «на уровень вверх»).

`$Sprite2D` — короткая запись `get_node("Sprite2D")`. Делают одно и то же.

:: code
В тренажёре сцены нет, поэтому детей создадим кодом. Узел создают через `Тип.new()`, ребёнка добавляют через `add_child()`. Подробно — в модуле 14. А пока смотри на `$`.
```gd
extends Node2D

func _ready():
	var label = Label.new()
	label.name = "HealthLabel"
	add_child(label)
	print_tree_pretty()

	$HealthLabel.text = "HP: 100"
	print($HealthLabel.text)
```
```out
 ┖╴Main
    ┖╴HealthLabel
HP: 100
```
`print_tree_pretty()` рисует дерево узлов — так же, как панель Scene.

:: code
Если узла с таким именем нет — ошибка. Это самая частая ошибка в Godot.
```gd
extends Node2D

func _ready():
	$Sprite.visible = false
```
fails: yes
Что проверить: имя узла (большие и маленькие буквы!) и путь. Если узел вложен глубже, путь нужен полный: `$Body/Sprite`.

:: text @onready — найти узел заранее
Писать `$HealthLabel` каждый раз длинно. Узел удобно положить в переменную. Но **вверху скрипта** узлов ещё нет — дети появляются чуть позже.

Для этого есть `@onready`: «заполни переменную, когда узел будет готов» — прямо перед `_ready`.

```gd
extends Node2D

@onready var label = $HealthLabel
@onready var sprite = $Sprite2D

func _ready():
	label.text = "HP: 100"
```

Так делают почти во всех скриптах Godot.

:: code
Совет: перетащи узел из дерева Scene в редактор кода, удерживая `Ctrl`. Godot сам напишет строку с `@onready` и правильным путём.
```gd
extends Node2D

@onready var hud = $HUD
@onready var hp_label = $HUD/HPLabel

func _ready():
	hp_label.text = "HP: 3"
	hud.visible = true
```
norun: yes
Этому коду нужна сцена с узлами `HUD` и `HUD/HPLabel`. В Godot создай их в дереве — и код заработает.

:: quiz
```tree
Player
├── Body
│   └── Sprite2D
└── Camera2D
```
Скрипт на `Player`. Как обратиться к `Sprite2D`?
[ ] `$Sprite2D` => `Sprite2D` не ребёнок `Player`, а внук. Нужен полный путь.
[x] `$Body/Sprite2D` => Верно. Сначала `Body`, потом внутри него `Sprite2D`.
[ ] `$Player/Body/Sprite2D` => Путь считается от узла со скриптом. `Player` писать не надо.

:: recap
- `$Имя` или `get_node("Имя")` — найти ребёнка. `$А/Б` — глубже, `..` — вверх.
- Ошибка `Node not found` — проверь имя и путь.
- `@onready var x = $Имя` — сохранить узел в переменную при старте.

## LESSON m09-p | Практика: скрипт на узле | 8 | practice
:: goals
- `_ready`, `_process`, `delta` и переменные скрипта вместе

:: task
Сделай «таймер выживания». Переменная скрипта `time_alive` начинается с 0. Каждый кадр прибавляй к ней `delta`. Когда наберётся 1 секунда или больше, напечатай `Прошла секунда!` — **один раз**.

В тренажёре 6 кадров по 0.25 секунды. Должно напечататься одно сообщение:
```text
Прошла секунда!
```
```gd
extends Node
# тренажёр: кадров=6 дельта=0.25

var time_alive = 0.0
var announced = false

func _process(delta):
	pass
```
```solution
extends Node
# тренажёр: кадров=6 дельта=0.25

var time_alive = 0.0
var announced = false

func _process(delta):
	time_alive += delta
	if time_alive >= 1.0 and not announced:
		print("Прошла секунда!")
		announced = true
```
```expect
Прошла секунда!
```
hint: `time_alive += delta` каждый кадр.
hint: Чтобы напечатать один раз, используй флажок `announced`: печатай, только если он `false`, и сразу ставь `true`.

:: recap
- Время в игре копят так: `time += delta`.
- Флажок-`bool` помогает сделать что-то один раз.
