# MODULE m02 | Узлы и сцены | Кирпичики, из которых собрана любая игра

## LESSON m02-1 | Узел — кирпичик с одной задачей | 6
:: goals
- Что такое узел
- Какие бывают узлы
- Что такое свойства узла

:: text Один узел — одна задача
visual: concept-m02
**Узел** (node) — главный кирпичик Godot. У каждого узла одна понятная задача.

Примеры:
- `Sprite2D` — показывает картинку.
- `Label` — показывает текст.
- `AudioStreamPlayer` — проигрывает звук.
- `Camera2D` — камера, которая смотрит на часть мира.
- `Timer` — считает время и сообщает «время вышло».

В Godot больше сотни типов узлов. Учить их все не нужно. Хватит десятка, и мы их пройдём.

:: text Цвет иконки подсказывает тип
У каждого узла в редакторе есть иконка. Цвет иконки — подсказка:

- **синий** — узлы для 2D (`Node2D`, `Sprite2D`, `Camera2D`);
- **красный** — узлы для 3D (`Node3D`, `Camera3D`);
- **зелёный** — интерфейс: кнопки, надписи (`Button`, `Label`);
- **серый/белый** — общие узлы без места в пространстве (`Node`, `Timer`).

:: text У узла есть свойства
**Свойство** — это настройка узла. Например, у `Sprite2D` есть:

- `position` — где он стоит;
- `rotation` — на сколько повёрнут;
- `scale` — во сколько раз увеличен;
- `texture` — какая картинка.

Свойства видны в **Inspector** (Инспекторе), когда узел выбран. Их можно менять мышкой, а позже — кодом.

**Аналогия:** узел — это лампа. Свойства — её ручки: яркость, цвет, направление.

:: quiz
Какой узел нужен, чтобы показать на экране надпись «Очки: 10»?
[ ] `Sprite2D` => Он показывает картинку, а не текст.
[x] `Label` => Верно. Label — узел для текста.
[ ] `Timer` => Он считает время и ничего не показывает.

:: quiz
Где посмотреть и поменять свойства узла?
[x] В Inspector, когда узел выбран => Верно.
[ ] В FileSystem => Там файлы проекта, а не свойства узлов.
[ ] Только в коде => Можно и в коде, но проще — в Инспекторе мышкой.

:: recap
- **Узел** — кирпичик с одной задачей.
- Цвет иконки: синий — 2D, красный — 3D, зелёный — интерфейс.
- **Свойства** — настройки узла. Видны в Inspector.

## LESSON m02-2 | Дерево узлов | 7
:: goals
- Что такое родитель и ребёнок
- Почему дети двигаются вместе с родителем
- Что такое корневой узел

:: text Узлы складываются в дерево
lab: repair-hierarchy
Узлы не лежат кучей. Они вложены друг в друга, как папки на компьютере.

Узел внутри другого узла называется **ребёнком** (child). Внешний узел — **родитель** (parent).

Вот как может выглядеть персонаж:

```tree
Player            ← родитель
├── Sprite2D      ← ребёнок: картинка
├── CollisionShape2D ← ребёнок: форма для столкновений
└── Camera2D      ← ребёнок: камера
```

Это называется **деревом узлов** (scene tree). Дерево растёт сверху вниз.

:: text Дети следуют за родителем
Главное правило дерева: **дети двигаются вместе с родителем**.

Двигаешь `Player` — картинка, форма и камера едут вместе с ним. Не нужно двигать каждую часть отдельно.

То же с поворотом, размером и видимостью. Спрятал родителя — спрятались и все дети.

**Аналогия:** рюкзак (родитель) и вещи в нём (дети). Переносишь рюкзак — вещи переезжают вместе с ним.

:: text Корень
У каждого дерева ровно один верхний узел. Он называется **корневым** (root).

В примере выше корень — `Player`. Обычно корень называют по смыслу сцены: `Player`, `Coin`, `Level1`, `Main`.

:: quiz
```tree
Car
├── Body
└── Wheel
```
Ты сдвинул узел `Car` вправо на 100 пикселей. Что станет с `Wheel`?
[x] Тоже сдвинется вправо на 100 => Верно. Ребёнок двигается вместе с родителем.
[ ] Останется на месте => Нет. Дети следуют за родителем.
[ ] Исчезнет => Ничего не исчезнет. Он просто переедет вместе с машиной.

:: quiz
```tree
Level
├── Player
│   └── Sprite2D
└── Enemy
```
Кто **родитель** узла `Sprite2D`?
[ ] `Level` => `Level` — это «дедушка». Родитель — ближайший узел сверху.
[x] `Player` => Верно. `Sprite2D` лежит прямо внутри `Player`.
[ ] `Enemy` => `Enemy` — сосед `Player`, а не родитель картинки.

:: recap
- Узлы вложены друг в друга и образуют **дерево**.
- Внутренний узел — **ребёнок**, внешний — **родитель**.
- Дети двигаются, поворачиваются и прячутся вместе с родителем.
- Верхний узел дерева — **корень**.

## LESSON m02-3 | Сцена — сохранённое дерево | 7
:: goals
- Что такое сцена и файл .tscn
- Почему игру делят на много сцен
- Как запустить сцену

:: text Сцена — это дерево в файле
**Сцена** (scene) — дерево узлов, сохранённое в файл. Файл сцены заканчивается на `.tscn`.

Например: `player.tscn`, `coin.tscn`, `level_1.tscn`.

:: text Игра — это много сцен
Обычно каждая отдельная «вещь» — своя сцена:

- `player.tscn` — персонаж;
- `coin.tscn` — монетка;
- `level_1.tscn` — уровень.

А потом сцены вставляют друг в друга. В уровень кладут персонажа и двадцать монеток. Монетку сделали один раз — используем много раз.

**Аналогия:** сцена — это формочка для печенья. Одна формочка — много одинаковых печенек.

```tree
Level1             (сцена level_1.tscn)
├── Player         ← это целая сцена player.tscn
├── Coin           ← сцена coin.tscn
├── Coin2          ← та же сцена ещё раз
└── Coin3          ← и ещё раз
```

:: text Главная сцена
У проекта есть **главная сцена** (main scene). С неё начинается игра, когда нажимаешь `F5`.

Первый раз Godot сам спросит, какую сцену сделать главной. Можно выбрать текущую: **Select Current**.

- `F5` — запустить игру с главной сцены.
- `F6` — запустить только ту сцену, что открыта сейчас. Удобно, чтобы проверить одну монетку.

:: quiz
Ты сделал сцену `coin.tscn` и хочешь 30 монеток на уровне. Что нужно?
[ ] Сделать 30 разных сцен => Не нужно. Одна сцена — сколько угодно копий.
[x] Вставить сцену монетки в уровень 30 раз => Верно. Сцену делают один раз и используют много раз.
[ ] Нарисовать 30 монеток на одной картинке => Тогда их нельзя будет собирать по одной.

:: quiz
Чем отличаются `F5` и `F6`?
[x] `F5` запускает игру с главной сцены, `F6` — открытую сейчас сцену => Верно.
[ ] Ничем => Отличаются: стартовая сцена разная.
[ ] `F6` останавливает игру => Остановить — `F8`.

:: recap
- **Сцена** — дерево узлов в файле `.tscn`.
- Каждая «вещь» в игре — своя сцена. Сцены вставляют друг в друга.
- **Главная сцена** запускается по `F5`. `F6` — открытая сцена.

## LESSON m02-4 | Практика: первая сцена | 10 | practice
:: goals
- Создать сцену руками
- Добавить надпись и картинку
- Запустить игру

:: steps Создаём сцену
lab: first-scene
visual: guide-m02-4-0
Открой свой проект из модуля 1.
- В панели **Scene** нажми **2D Scene**. Появится узел `Node2D`.
- Дважды кликни по `Node2D` и переименуй его в `Main`. Нажми Enter.
- Нажми `Ctrl+S`. Сохрани сцену как `main.tscn` в корень проекта (`res://`).

:: steps Добавляем надпись
visual: guide-m02-4-1
- Выбери узел `Main`. Нажми `Ctrl+A` (или **+** над деревом) — это **Add Child Node** (Добавить дочерний узел).
- В поиске набери `Label`. Выбери **Label** и нажми **Create**.
- Справа в **Inspector** найди поле **Text**. Напиши: `Привет, Godot!`
- В центре окна перетащи надпись мышкой ближе к середине. Это меняет её `position`.

:: steps Добавляем картинку
visual: guide-m02-4-2
- Выбери `Main` и снова добавь ребёнка: на этот раз **Sprite2D**.
- В панели **FileSystem** найди файл `icon.svg`.
- Перетащи `icon.svg` мышкой в поле **Texture** в Инспекторе. Появится логотип Godot.
- Передвинь картинку мышкой, чтобы она не закрывала надпись.

:: steps Запускаем
visual: guide-m02-4-3
- Нажми `F5`. Godot спросит про главную сцену — нажми **Select Current**.
- Откроется окно игры. Там надпись и логотип.
- Закрой окно игры или нажми `F8`.

> Если окно игры серое и пустое, проверь, что надпись и картинка стоят внутри синей рамки в редакторе. Синяя рамка — это экран игры.

:: quiz
Где в редакторе видно, какую часть мира покажет экран игры?
[x] Синяя рамка в окне 2D => Верно. Всё, что внутри рамки, видно в игре (если нет камеры).
[ ] Панель FileSystem => Там файлы.
[ ] Это никак не узнать => Узнать можно: по синей рамке.

:: recap
- Новая 2D-сцена: **Scene → 2D Scene**, сохранить — `Ctrl+S`.
- Добавить ребёнка: `Ctrl+A` (**Add Child Node**).
- Картинку ставят, перетаскивая файл в свойство **Texture**.
- Синяя рамка в 2D — экран игры.

## LESSON m02-workshop | Мастерская: сцена, которую можно пересобрать | 12 | practice
:: goals
- Собрать сцену по назначению узлов, а не по чужим названиям
- Проверить текстуру, родителя и результат запуска

:: text Сначала договоримся о результате
Нужна небольшая открытка: картинка и подпись. Корень хранит сцену, `Sprite2D` рисует картинку, `Label` показывает текст. Названия и содержание подписи выбираешь сам.

Открой [«Собери первую сцену»](#/practice/first-scene). Здесь проверяется устройство сцены, а не совпадение с чужой открыткой. Вернуться к этому шагу можно ссылкой под редактором.

:: text Что именно ты выбираешь
В **Scene** выбирают узел, в **FileSystem** — файл. Это разные вещи: файл картинки сам по себе не становится частью сцены. У `Sprite2D` должно быть заполнено свойство **Texture** в Inspector.

Если картинка не появилась, сначала проверь Texture, затем положение и масштаб. Создавать второй спрайт наугад не нужно.

:: steps Повтори открытку в Godot
visual: workshop-m02
- Создай новую 2D-сцену с корнем Node2D. Сохрани её как postcard.tscn.
- Выбери корень и добавь Sprite2D. Перетащи icon.svg из FileSystem в его Texture.
- Снова выбери корень, добавь Label и заполни Text своей подписью.
- Размести подпись рядом с картинкой, сохрани сцену и запусти текущую сцену через F6.

Ожидаемый результат: в запущенной сцене видны и картинка, и твоя подпись. Закрой окно игры, а не весь редактор.

:: text Маленький эксперимент
Сдвинь корень на 40 пикселей вправо. Оба ребёнка должны переместиться вместе с ним. Затем верни корень назад.

Если один объект остался на месте, посмотри на отступы в дереве: он мог стать соседом корня или ребёнком другого узла. Для отдельной тренировки есть [ремонт дерева](#/practice/repair-hierarchy).

:: quiz
Ты сменил имя Label, но оставил его тип, текст и родителя. Должна ли открытка перестать работать?
[x] Нет, название не определяет способность Label показывать текст => Верно. Позже имя понадобится для путей в коде, но здесь кода с путями ещё нет.
[ ] Да, любой узел обязан называться как в примере => Пример имени не является требованием к сцене.

:: recap
- Выбор узла и выбор файла — разные действия.
- Сначала проверь свойства и дерево, затем запуск.
- Результат можно получить с собственными именами и подписью.
