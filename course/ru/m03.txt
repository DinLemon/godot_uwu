# MODULE m03 | Первый скрипт | Учим узел говорить

## LESSON m03-1 | Что такое скрипт | 6
:: goals
- Что такое скрипт
- Как прикрепить скрипт к узлу
- Как выглядит пустой скрипт

:: text Скрипт — инструкция для узла
visual: concept-m03
Узел сам по себе ничего не решает. `Sprite2D` просто показывает картинку и стоит на месте.

**Скрипт** — это текст с командами на языке **GDScript**. Ты прикрепляешь его к узлу, и узел начинает его выполнять.

**Аналогия:** узел — актёр, скрипт — его роль. Без роли актёр стоит молча.

Файл скрипта заканчивается на `.gd`. Например: `player.gd`.

:: steps Прикрепляем скрипт
visual: guide-m03-1-0
Открой сцену `main.tscn` из прошлого модуля.
- В панели **Scene** выбери узел `Main`.
- Нажми иконку свитка с плюсом над деревом — **Attach Script** (Прикрепить скрипт). Или правый клик по узлу → **Attach Script**.
- В окне всё оставь как есть. Путь будет `res://main.gd`. Нажми **Create**.
- Откроется вкладка **Script** с текстом скрипта.

:: text Что написал Godot
Godot создал заготовку. Примерно такую:

```gd
extends Node2D


# Called when the node enters the scene tree for the first time.
func _ready() -> void:
	pass # Replace with function body.


# Called every frame. 'delta' is the elapsed time since the previous frame.
func _process(delta: float) -> void:
	pass
```

Разберём по строчке в следующих уроках. Сейчас главное:
- `extends Node2D` — «этот скрипт для узла типа Node2D»;
- `func _ready() -> void:` — код ниже выполнится, когда узел появится в игре;
- `pass` — «ничего не делать». Пустое место, чтобы было что-то написано.

Кусочки `-> void` и `: float` — это подсказки о типах. Они необязательные. Пока не обращай на них внимания, разберём их в модулях 4 и 7. В примерах курса их часто нет — код работает и так.

:: quiz
Какое расширение у файла скрипта GDScript?
[ ] `.tscn` => Это файл сцены.
[x] `.gd` => Верно.
[ ] `.godot` => Это файл проекта `project.godot`.

:: recap
- **Скрипт** — текст с командами на GDScript. Прикрепляется к узлу.
- Файл скрипта — `.gd`. Прикрепить: **Attach Script**.
- `extends` говорит, для какого типа узла скрипт.

## LESSON m03-2 | print и _ready | 7
:: goals
- Как напечатать текст командой `print`
- Когда выполняется `_ready`
- Как запускать код в тренажёре

:: text Команда print
`print` печатает текст в панель **Output** (Вывод) внизу редактора Godot. Игрок её не видит. Это записки для тебя, разработчика.

```gd
print("Привет!")
```

Текст пишут в кавычках `" "`. Без кавычек Godot подумает, что это имя чего-то в коде.

:: text Где писать команды
Команды пишут **внутри функции**. Функция `_ready` выполняется один раз, когда узел появляется в игре.

Строки внутри функции сдвинуты вправо — это **отступ**. Отступ показывает: «эти строки лежат внутри `_ready`».

```gd
extends Node

func _ready():
	print("Я внутри _ready")
```

Отступ делают клавишей `Tab`.

:: code
Это тренажёр. Нажми **▶ Запустить**. Результат появится под кодом — так же, как в панели Output в Godot.
```gd
extends Node

func _ready():
	print("Привет, Godot!")
	print("Это мой первый скрипт.")
```
```out
Привет, Godot!
Это мой первый скрипт.
```
Поменяй текст в кавычках и запусти ещё раз. Команды выполняются сверху вниз, по очереди.

:: text Тренажёр и Godot
Каждый пример в курсе начинается со строк:

```gd
extends Node

func _ready():
```

Это настоящий код Godot. Пример можно скопировать кнопкой «Скопировать», вставить в скрипт в Godot и запустить `F6`. Получится то же самое.

> В примерах `extends Node`. Это самый простой узел. В Godot у тебя может стоять `extends Node2D` — для печати это не важно.

:: fill
Заполни пропуски, чтобы программа напечатала `Hello`.
```gd
extends Node

func ___():
	___("Hello")
```
= _ready
= print
explain: `_ready` выполняется при старте узла, `print` печатает текст.

:: task
Напиши программу, которая печатает три строки:
```text
Раз
Два
Три
```
```gd
extends Node

func _ready():
	print("Раз")
```
```solution
extends Node

func _ready():
	print("Раз")
	print("Два")
	print("Три")
```
```expect
Раз
Два
Три
```
hint: Каждая строка — отдельная команда `print`.
hint: Не забудь отступ (Tab) перед каждой командой внутри `_ready`.

:: recap
- `print("текст")` печатает в панель **Output**.
- `func _ready():` — код выполнится один раз при появлении узла.
- Строки внутри функции пишутся с **отступом** (`Tab`).

## LESSON m03-3 | Ошибки — это подсказки | 7
:: goals
- Почему ошибки — это нормально
- Как читать сообщение об ошибке
- Три самые частые ошибки новичка

:: text Ошибки будут. Это хорошо
Ошибки бывают у всех. Даже у тех, кто пишет код двадцать лет.

Сообщение об ошибке — не наказание. Это **подсказка**: Godot говорит, в какой строке и что ему непонятно.

В Godot ошибки видны внизу редактора скрипта красным, а строка подсвечивается. В тренажёре — под кодом, с объяснением по-русски.

:: code
Здесь забыто двоеточие `:` после `_ready()`. Запусти и прочитай ошибку.
```gd
extends Node

func _ready()
	print("Привет")
```
fails: yes
Сообщение начинается с номера строки. Потом идёт текст как в Godot: `Expected ":" after function declaration` — «Ожидалось двоеточие после объявления функции». Добавь `:` и запусти снова.

:: code
А здесь потерялся отступ.
```gd
extends Node

func _ready():
print("Привет")
```
fails: yes
Godot ждёт, что после строки с двоеточием будет хотя бы одна строка **со сдвигом вправо**. Поставь курсор перед `print` и нажми `Tab`.

:: code
И третья частая ошибка — забытые кавычки.
```gd
extends Node

func _ready():
	print(Привет)
```
fails: yes
Без кавычек `Привет` выглядит как имя переменной. Такой переменной нет, поэтому Godot говорит `not declared` — «не объявлено». Добавь кавычки: `"Привет"`.

:: quiz
Ты видишь ошибку `Identifier "Hello" not declared in the current scope.` Что, скорее всего, случилось?
[x] Забыты кавычки вокруг текста => Верно. Без кавычек Hello — это имя, а не текст.
[ ] Забыто двоеточие => Тогда была бы ошибка `Expected ":"`.
[ ] Godot сломался => Godot в порядке. Он просто не нашёл такое имя.

:: recap
- Ошибка — подсказка: номер строки + что не так.
- Частые ошибки: нет `:`, нет отступа, нет кавычек.
- Читай сообщение спокойно, слово за словом.

## LESSON m03-4 | Комментарии | 4
:: goals
- Что такое комментарий
- Зачем он нужен

:: text Записки в коде
**Комментарий** — текст после знака `#`. Godot его пропускает. Это записка для людей.

```gd
# Это комментарий. Godot его не читает.
print("А это команда") # комментарий можно писать и после команды
```

Зачем:
- объяснить себе через неделю, что делает код;
- временно «выключить» строку, не удаляя её.

> В Godot выдели строки и нажми `Ctrl+K` — они станут комментариями. Ещё раз `Ctrl+K` — вернутся обратно.

:: code
Запусти. Сколько строк напечатается?
```gd
extends Node

func _ready():
	print("один")
	# print("два")
	print("три") # print("четыре")
```
```out
один
три
```
Строки после `#` не выполняются.

:: quiz
Что напечатает `print("Привет") # мир`?
[x] `Привет` => Верно. Всё после `#` — комментарий.
[ ] `Привет # мир` => `#` стоит после кавычек, значит это уже комментарий.
[ ] Ошибку => Ошибки нет. Комментарий после команды — нормально.

:: recap
- `#` — начало комментария. Godot его пропускает.
- `Ctrl+K` в Godot превращает строки в комментарии и обратно.
