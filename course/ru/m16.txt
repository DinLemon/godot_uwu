# MODULE m16 | Камера и уровни | Камера за игроком и уровни из плиток

## LESSON m16-1 | Camera2D | 7
:: goals
- Зачем нужна камера
- Как сделать, чтобы она следила за игроком
- Ограничения и сглаживание

:: text Окно в большой мир
Без камеры игра показывает только синюю рамку — кусок мира от (0, 0). Если уровень больше экрана, персонаж убежит за край.

**Camera2D** — окно, через которое мы смотрим на мир. Где камера — то и видно.

Самый простой способ: сделать камеру **ребёнком игрока**. Дети двигаются с родителем — камера поедет за игроком сама.

:: steps Камера за игроком
- Открой `player.tscn`. Добавь в `Player` узел **Camera2D**.
- Открой `level.tscn` и нажми `F6`. Камера следует за персонажем.
- В Инспекторе камеры включи **Position Smoothing → Enabled**. Камера будет догонять плавно, а не дёргаться.
- В разделе **Limit** поставь границы: **Left** `0`, **Bottom** — низ уровня. Камера не покажет пустоту за краями.

:: text Полезные свойства
- `zoom` — приближение. `Vector2(2, 2)` — в 2 раза ближе, `Vector2(0.5, 0.5)` — дальше.
- `offset` — сдвиг: например, смотреть чуть вперёд по ходу движения.
- `limit_left`, `limit_right`, `limit_top`, `limit_bottom` — края мира.
- `position_smoothing_enabled` — плавное следование.

!> Если в сцене несколько камер, работает одна — та, что `enabled` и вошла в игру первой. Сделать главной: `make_current()`.

:: quiz
Как проще всего заставить камеру следить за игроком?
[x] Сделать Camera2D ребёнком узла игрока => Верно. Дети двигаются вместе с родителем.
[ ] Каждый кадр копировать позицию игрока в камеру => Так можно, но это лишний код.
[ ] Камера следит сама за любым CharacterBody2D => Нет, камере нужно указать, где быть.

:: recap
- **Camera2D** показывает часть мира вокруг себя.
- Камера-ребёнок игрока следует за ним сама.
- `zoom` — приближение, **Limit** — границы, **Position Smoothing** — плавность.

## LESSON m16-2 | Уровень из плиток: TileMapLayer | 10
:: goals
- Что такое тайлы
- Как нарисовать уровень кистью
- Как добавить столкновения плиткам

:: text Уровень из плиток
Рисовать уровень одной огромной картинкой неудобно. Обычно уровень собирают из **плиток** (tiles) — маленьких квадратиков 16×16 или 32×32 пикселя: земля, трава, кирпич, вода.

**Аналогия:** конструктор или мозаика. Набор деталей один, а уровней можно собрать сколько угодно.

В Godot 4 для этого два понятия:
- **TileSet** — набор плиток (вырезан из картинки-атласа) и их свойства: столкновения, тип.
- **TileMapLayer** — узел-слой, на котором плитками рисуют уровень.

> В старых уроках встречается узел `TileMap`. В новых версиях Godot его заменил **TileMapLayer**. Идея та же: один TileMapLayer — один слой.

:: steps Создаём TileSet
Скачай набор плиток (tileset), например на [kenney.nl](https://kenney.nl/assets) — «Pixel Platformer». Перетащи картинку в FileSystem.
- Открой `level.tscn`. Добавь в `Level` узел **TileMapLayer**. Назови `Ground`.
- В Инспекторе в поле **Tile Set** выбери **New TileSet**. Кликни по нему и поставь **Tile Size** как у твоих плиток (например 18×18 или 16×16).
- Внизу откройте панель **TileSet**. Перетащи картинку с плитками в левый список **Tiles**.
- Godot спросит: «Автоматически создать плитки?» — **Yes**.

:: steps Рисуем
- Внизу открой панель **TileMap** (рядом с TileSet).
- Выбери плитку, включи кисть (**Paint**, клавиша `D`) и рисуй в окне 2D левой кнопкой мыши.
- Правая кнопка мыши — стереть.
- Есть инструменты: **Line** (линия), **Rect** (прямоугольник), **Bucket** (заливка).

:: steps Столкновения для плиток
Плитки пока «призрачные» — персонаж падает сквозь них.
- Выбери TileMapLayer. В Инспекторе раскрой **Tile Set** → **Physics Layers** → **Add Element**.
- Внизу в панели **TileSet** перейди на вкладку **Paint** (Покраска). В списке свойств выбери **Physics Layer 0**.
- Кликай по плиткам земли в атласе — на них появится синий квадрат формы. Это их столкновение.
- Удали старый пол `Floor` из модуля 12. Запусти — персонаж стоит на плитках.

:: quiz
Чем TileSet отличается от TileMapLayer?
[x] TileSet — набор плиток и их свойства; TileMapLayer — слой, где из них нарисован уровень => Верно.
[ ] Это одно и то же => Нет. Набор и рисунок — разные вещи.
[ ] TileMapLayer — старое название TileSet => Старое название у TileMapLayer — TileMap.

:: recap
- Уровень рисуют плитками. **TileSet** — набор, **TileMapLayer** — слой с рисунком.
- Рисование: панель **TileMap**, кисть `D`, стереть — правая кнопка.
- Столкновения: **Physics Layers** в TileSet + покраска формы на плитках.

## LESSON m16-3 | Плитки из кода | 6
:: goals
- Как узнать и поменять плитку кодом
- Переход между пикселями и клетками

:: text Клетки и пиксели
У TileMapLayer своя сетка. Позиция плитки — это **клетка** (Vector2i — вектор из целых чисел), а не пиксели.

- `local_to_map(позиция)` — в какой клетке точка;
- `map_to_local(клетка)` — центр клетки в пикселях;
- `get_cell_source_id(клетка)` — есть ли там плитка (`-1` — пусто);
- `set_cell(клетка, источник, координаты_в_атласе)` — поставить плитку;
- `erase_cell(клетка)` — убрать плитку.

:: code
Разрушаемый блок: игрок ударил по клетке под собой — блок исчез.
```gd
extends CharacterBody2D

@onready var ground: TileMapLayer = $"../Ground"

func break_block_below():
	var cell = ground.local_to_map(global_position + Vector2(0, 20))
	if ground.get_cell_source_id(cell) != -1:
		ground.erase_cell(cell)
		print("Блок разрушен: ", cell)
```
norun: yes
`$"../Ground"` — путь к соседу: подняться к родителю и взять `Ground`. Кавычки нужны из-за точек.

:: quiz
Какой тип у координат клетки в TileMapLayer?
[ ] `Vector2` => Клетки — целые номера, поэтому `Vector2i`.
[x] `Vector2i` => Верно. «i» — integer, целые числа.
[ ] `int` => Клетка — это пара чисел: столбец и строка.

:: recap
- Клетки сетки — `Vector2i`.
- `local_to_map` и `map_to_local` переводят между пикселями и клетками.
- `set_cell`, `erase_cell`, `get_cell_source_id` — менять уровень кодом.
