## LESSON m24-1 | Платформер: почему лисёнок снова падает | 12 | practice
:: goals
- Испытать прыжок и приземление в маленькой игре
- Отличить скорость от изменения скорости

:: text Сначала поиграй
game: platformer
Собери три звезды на ступеньках. Сначала попробуй обычный прыжок, затем удержание пробела. Второго толчка в воздухе не будет: прыжок разрешён только после приземления.

Это учебная браузерная игра. Числовой пример ниже объясняет гравитацию, а для сборки физической сцены понадобится настоящий Godot.

:: text Какие узлы нужны
```tree
Level · Node2D
├── Player · CharacterBody2D
│   ├── Sprite2D
│   └── CollisionShape2D
├── Platforms · Node2D
│   └── StaticBody2D + CollisionShape2D
└── Stars · Node2D
    └── Area2D + Sprite2D + CollisionShape2D
```
Картинка героя не отвечает за физику. Тело движется, форма определяет столкновение, Area2D звезды сообщает о сборе. При сборе увеличь счёт и удали звезду через `queue_free()`.

:: code
Прыжок задаёт отрицательную скорость по Y. Гравитация постепенно возвращает её к положительной. Здесь проверяем только скорость, без сцены и столкновений.
```gd
extends Node

func _ready():
	var velocity_y = -400.0
	var gravity = 850.0
	var delta = 0.1
	for frame in range(4):
		velocity_y += gravity * delta
		print(int(velocity_y))
```
```out
-315
-230
-145
-60
```
Отрицательная скорость означает движение вверх. Она ещё не стала положительной, поэтому в этом коротком опыте вершина прыжка пока впереди.

:: text Измени и предскажи
Увеличь число кадров до 6. До запуска найди кадр, на котором скорость станет положительной. Затем сравни вывод.

Вернись к игре и поставь силу прыжка 340, затем 480. Предскажи, до какой ступеньки дотянешься. Меняй один параметр, чтобы сравнение оставалось понятным.

:: text Перенос в Godot
1. Открой персонажа из модуля 12 и проверь `CharacterBody2D` с непустой формой.
2. В `_physics_process(delta)` прибавляй гравитацию к `velocity.y`; при `is_on_floor()` и новом нажатии прыжка присваивай отрицательную скорость.
3. После вычисления скорости вызывай `move_and_slide()`. Не умножай перед ним всю velocity на delta.
4. Расставь три платформы и звезды. Проверь пол, прыжок с края и повторный прыжок после приземления.

Для отдельного опыта открой [практику прыжка](#/practice/jump-playground). [Документация CharacterBody2D](https://docs.godotengine.org/en/stable/tutorials/physics/using_character_body_2d.html) объясняет движение тела и столкновения.

:: quiz
Что меняет прибавление gravity * delta к velocity.y?
[x] Скорость по вертикали за прошедшее время => Скорость затем используется при движении тела.
[ ] Количество звёзд на уровне => Счёт меняется в логике сбора, а не от гравитации.
[ ] Только картинку Sprite2D => Скорость принадлежит движению тела.

:: recap
- Прыжок задаёт скорость вверх; гравитация меняет её каждый физический шаг.
- Условие is_on_floor ограничивает повторный прыжок.
- Испытай высоту прыжка, приземление и сбор предмета отдельно.

## LESSON m24-2 | Приключение: одинаковая скорость по диагонали | 12 | practice
:: goals
- Собрать посылки, обходя стены
- Узнать, почему два направления не должны давать ускорение

:: text Пройди маршрут
game: adventure
Собери четыре посылки. Лисёнок может ходить по восьми направлениям. Стены остаются препятствиями даже при движении по диагонали.

Сначала найди проходы и пройди маршрут на скорости 180. Затем сравни с 100 и 260. Большая скорость не всегда удобнее в узком проходе.

:: text Сцена приключения
```tree
World · Node2D
├── Player · CharacterBody2D
│   ├── Sprite2D
│   └── CollisionShape2D
├── Walls · StaticBody2D
│   └── CollisionShape2D
└── Parcel · Area2D
    ├── Sprite2D
    └── CollisionShape2D
```
В приключении с видом сверху обычно не нужна гравитация платформера. Управление задаёт оба компонента `velocity`. `Input.get_vector("left", "right", "up", "down")` ограничивает длину направления, чтобы диагональ не давала лишнюю скорость.

:: code
Сравним нормализованные направления. Это отдельный опыт с Vector2, без ввода и физики.
```gd
extends Node

func _ready():
	var right = Vector2(1, 0).normalized()
	var diagonal = Vector2(1, 1).normalized()
	print(roundi((right * 180).length()))
	print(roundi((diagonal * 180).length()))
```
```out
180
180
```
`normalized()` сохраняет направление, но делает длину равной 1. После умножения на 180 обе скорости имеют одинаковую длину.

:: text Сломай одно правило
Убери `.normalized()` у diagonal в коде. Предскажи: скорость останется 180 или вырастет? Запусти и сравни.

Число около 255 показывает причину «быстрой диагонали». Это свойство длины вектора `(1, 1)`, а не ускорение, которое специально добавил движок.

:: text Перенос в Godot
1. Настрой четыре действия в Input Map. Имена в коде должны совпасть с настройками.
2. Для Player используй CharacterBody2D и подходящую форму. Для движения без пола выбери Motion Mode → Floating.
3. Получи направление через `Input.get_vector`, умножь на скорость и запиши в velocity; вызови `move_and_slide()`.
4. Добавь посылке Area2D. В обработчике body_entered проверь игрока, увеличь счёт и удали посылку.

Критерий: одна посылка увеличивает счёт один раз; стену нельзя пересечь. [Официальный пример движения](https://docs.godotengine.org/en/stable/tutorials/2d/2d_movement.html) показывает ту же связь Input Map и скорости.

:: quiz
Зачем нормализовать направление (1, 1) перед умножением на скорость?
[x] Чтобы его длина не давала ускорение по диагонали => Два ненулевых компонента образуют более длинный вектор.
[ ] Чтобы отключить столкновения => Нормализация не меняет физические формы.
[ ] Чтобы монеты исчезали => Сбор предметов — другая логика.

:: recap
- Вид сверху использует горизонтальный и вертикальный ввод без обязательной гравитации.
- Скорость — вектор: сравнивай его длину.
- Отдельно проверь стены, диагональ и повторный сбор предмета.

## LESSON m24-3 | Арканоид: отскок — это изменение направления | 12 | practice
:: goals
- Испытать отскок от стены, платформы и блока
- Разделить скорость шара и число оставшихся блоков

:: text Разбей восемь блоков
game: ricochet
Лови шар платформой. Попадание ближе к краю меняет направление сильнее, чем удар по центру. Нижняя граница открыта: пропущенный шар завершает попытку.

Сначала попробуй скорость 180. После нескольких отскоков увеличь её до 300 и сравни, сколько времени остаётся на реакцию.

:: text Узлы и события
```tree
Arena · Node2D
├── Ball · CharacterBody2D
│   ├── Sprite2D
│   └── CollisionShape2D
├── Paddle · CharacterBody2D
├── Brick · StaticBody2D
└── LossZone · Area2D
```
В Godot столкновение может вернуть нормаль поверхности. Отражение скорости от неё меняет направление движения. Счёт блоков — отдельное состояние; отскок не должен сам по себе добавлять очки несколько раз.

:: code
Для вертикальной стенки достаточно поменять знак X. Длина скорости сохранится. Это числовая модель одного отскока.
```gd
extends Node

func _ready():
	var velocity = Vector2(120, -160)
	print(roundi(velocity.length()))
	velocity.x = -velocity.x
	print(int(velocity.x))
	print(int(velocity.y))
	print(roundi(velocity.length()))
```
```out
200
-120
-160
200
```
Для горизонтальной поверхности меняют знак Y. Для произвольного наклона используют отражение по нормали, а не набор проверок «слева/справа».

:: text Придумай граничный случай
Проверь удар по центру и по краю платформы. В обоих случаях шар должен полететь вверх. Если разрешить почти горизонтальный отскок, игра может надолго застрять в движении из стороны в сторону.

В браузерной модели угол ограничен, а скорость после отскока сохраняется. Подумай, какие значения стоит ограничить в своей игре.

:: text Перенос в Godot
1. Для шара заведи Vector2 скорости. В `_physics_process` передавай `velocity * delta` в `move_and_collide()`.
2. Если вернулось столкновение, вычисли новую скорость через `velocity.bounce(collision.get_normal())`.
3. Если столкновение относится к блоку, сначала пометь блок разрушенным, увеличь счёт, затем удали блок.
4. При попадании в нижнюю зону проигрыша останови движение и покажи кнопку новой попытки.

Здесь используется `move_and_collide`, которому нужно смещение за шаг. Не переноси правило про delta вслепую на `move_and_slide`: у него другой контракт.

:: quiz
Шар ударился о вертикальную стенку без изменения своей скорости по модулю. Какой компонент меняет знак?
[x] X => Направление по горизонтали отражается, вертикальный компонент сохраняется.
[ ] Y => Это был бы отскок от горизонтальной поверхности.
[ ] Оба всегда => Так шар развернулся бы точно назад даже при косом ударе.

:: recap
- Направление и длина скорости — разные характеристики.
- Отскок от наклонной поверхности вычисляется по нормали.
- Счёт, удаление блока и проигрыш проверяются отдельно от отскока.

## LESSON m24-4 | Раннер: кто движется — герой или мир | 10 | practice
:: goals
- Увидеть движение мира относительно неподвижного героя
- Связать таймер появления с созданием экземпляров

:: text Доставь посылку
game: runner
Перепрыгни пять ящиков. Лисёнок остаётся слева; ящики приезжают справа. Победа засчитывается, когда ящик полностью оказался позади героя.

Поставь игру на паузу перед прыжком. Обрати внимание: вместе с движением остановилось и появление новых ящиков.

:: text Из чего собран раннер
```tree
Run · Node2D
├── Player · CharacterBody2D
├── Ground · StaticBody2D
├── Obstacles · Node2D
├── SpawnTimer · Timer
└── HUD · CanvasLayer
```
SpawnTimer сообщает «пора создать ящик». Сцена-шаблон создаётся через `instantiate()`, получает начальную позицию справа и движется влево. За левым краем её можно удалить.

:: code
Положение препятствия зависит от времени. В этом опыте нет столкновений — только движение по X.
```gd
extends Node

func _ready():
	var obstacle_x = 640.0
	var world_speed = 200.0
	var delta = 0.25
	for frame in range(4):
		obstacle_x -= world_speed * delta
		print(int(obstacle_x))
```
```out
590
540
490
440
```
За секунду ящик сдвинулся на 200. Измени delta и число кадров так, чтобы суммарное время осталось равным секунде: итоговая координата должна остаться той же.

:: text Частота и скорость — разные настройки
При той же частоте появления высокая скорость увеличивает расстояние между ящиками, но сокращает время от их появления до встречи с героем. Если нужна плотная череда препятствий, придётся менять и интервал.

Нельзя считать, что «быстрее» автоматически означает одну и ту же сложность. Испытай комбинацию настроек, а не только одно число.

:: text Перенос в Godot
1. Создай отдельную obstacle.tscn с телом, формой и картинкой.
2. Подключи timeout таймера к созданию экземпляра. Интервал задай в Inspector.
3. Передавай скорость мира препятствиям. Считай пройденный ящик один раз, отдельным флагом.
4. При проигрыше останови таймер, героя и препятствия. Новая попытка должна удалить старые ящики и сбросить счёт.

Для настройки события отдельно используй [практику таймера](#/practice/timer-event).

:: quiz
Игра на паузе, но SpawnTimer продолжает создавать ящики. Что произойдёт после продолжения?
[x] В мире могут оказаться лишние препятствия => Остановка только картинки не останавливает игровую логику.
[ ] Ничего: невидимый таймер не может работать => Видимость и отсчёт времени не связаны автоматически.

:: recap
- Ощущение бега можно создать движением окружения.
- Скорость мира и интервал появления — разные параметры.
- Пауза и перезапуск должны охватывать все части игрового цикла.

## LESSON m24-5 | Головоломка: девять огней и один массив | 12 | practice
:: goals
- Связать клетку поля с индексом массива
- Проверить соседей, не выходя за границы

:: text Зажги маяк
game: puzzle
Нужно включить все девять огней. Начальное поле получено из готового решения несколькими допустимыми ходами: оно решаемо при обоих правилах.

Попробуй один и тот же огонь дважды. Переключение вернёт затронутые клетки в прежнее состояние, но счётчик ходов увеличится.

:: text Поле не обязано быть девятью переменными
Храни огни в массиве из девяти bool. Для клетки `(x, y)` индекс равен `y * 3 + x`, где x и y от 0 до 2.

```tree
Puzzle · Control [script]
├── GridContainer · Columns = 3
│   └── Button × 9
├── MovesLabel · Label
└── RestartButton · Button
```
При клике кнопка передаёт свой индекс функции переключения. После изменения данных обновляются изображения кнопок и проверка победы.

:: code
Пока переключим только выбранную клетку и посчитаем включённые огни.
```gd
extends Node

func _ready():
	var lights = [true, false, true, false, true, false, true, false, true]
	var x = 1
	var y = 0
	var index = y * 3 + x
	lights[index] = not lights[index]
	var lit = 0
	for light in lights:
		if light:
			lit += 1
	print(index)
	print(lit)
```
```out
1
6
```
Победа — это не «совершил девять ходов», а «все девять значений true». Число ходов и состояние поля отвечают на разные вопросы.

:: text Проверь угол и край
Для правила «крест» нужны выбранная клетка и соседи сверху, снизу, слева и справа. В углу соседей меньше. Сначала проверь координаты соседа на диапазон 0…2 и только затем вычисляй индекс.

Простое `index - 1` ошибочно соединит начало строки с концом предыдущей. Поэтому клетка 2 не является левой соседкой клетки 3 при нумерации с нуля.

:: text Перенос в Godot
1. Добавь GridContainer с Columns = 3 и девять кнопок.
2. Создай массив bool. Свяжи pressed каждой кнопки с общей функцией, передавая индекс через bind.
3. Для каждого допустимого соседа инвертируй значение; затем одним проходом обнови подписи или цвета всех кнопок.
4. Сравни угол, центральную клетку и повторный клик. После победы запрети дальнейшие изменения до перезапуска.

В игре можно переключить правило на «строка». Заметь, что представление данных осталось тем же: меняется только набор затронутых индексов.

:: quiz
Индексы идут по строкам с нуля. Как получить индекс клетки (2, 1) на поле шириной 3?
[x] 1 * 3 + 2 = 5 => Сначала пропускаем целую строку, затем смещаемся по X.
[ ] 2 * 3 + 1 = 7 => Здесь X и Y поменялись местами.
[ ] 2 + 1 = 3 => Так не учитывается ширина строки.

:: recap
- Массив хранит данные, кнопки показывают их.
- Соседей удобнее проверять по координатам.
- Условие победы опирается на поле, а не на число кликов.

## LESSON m24-6 | Кликер: экономика без денег из воздуха | 10 | practice
:: goals
- Разделить событие кнопки, изменение данных и отображение
- Проверить покупку на границе цены

:: text Открой лавку
game: shop
Заработай монеты и купи три зелья. Сначала нажми покупку с пустым кошельком. Затем накопи ровно цену: покупка должна пройти и оставить ноль монет.

Измени цену на 3 или 8. Новый опыт начнётся с пустым кошельком, чтобы результаты можно было сравнить честно.

:: text Данные — источник истины
```tree
Shop · Control [script]
├── WalletLabel · Label
├── EarnButton · Button
├── BuyButton · Button
└── InventoryLabel · Label
```
Счёт хранится в переменной или словаре, а Label только показывает его. Не вытаскивай число обратно из текста «Монеты: 12», чтобы выполнить покупку: подпись может измениться или быть переведена.

:: code
Попытка покупки проверяется до изменения кошелька и инвентаря. Это модель двух кликов по кнопке покупки.
```gd
extends Node

var state = {"coins": 5, "potions": 0}

func buy(price):
	if state["coins"] < price:
		print("Отказ")
		return
	state["coins"] -= price
	state["potions"] += 1
	print("Куплено")

func _ready():
	buy(5)
	buy(5)
	print(state["coins"])
	print(state["potions"])
```
```out
Куплено
Отказ
0
1
```
Вторая покупка ничего не списывает и не добавляет. Ранний return защищает оба изменения.

:: text Четыре случая вместо одного
Проверь пустой кошелёк, сумму на одну монету меньше цены, точную цену и сумму больше цены. Сравни остаток и инвентарь после каждого клика.

После третьего зелья браузерная игра завершает опыт. Кнопки больше не меняют данные до перезапуска — это тоже часть правила, которую стоит проверить.

:: text Перенос в Godot
1. Подключи pressed кнопки заработка к увеличению монет.
2. Подключи pressed покупки к функции с проверкой цены.
3. После успешного изменения вызови общую функцию обновления HUD: она перепишет обе надписи.
4. Запрети покупки после победы. Перезапуск должен сбросить и данные, и подписи.

В [мастерской магазина](#/l/m08-workshop) разобрана та же проверка со списком предметов. Для подключения кнопки есть [практика сигналов](#/practice/button-signal).

:: quiz
Почему нельзя менять только текст «Зелья: 1», забыв обновить данные?
[x] Следующая покупка и сохранение прочитают старое состояние => Отображение должно следовать за данными.
[ ] Label всегда сам обновляет словарь => Между ними нет такой автоматической связи.

:: recap
- Событие запускает правило, правило меняет данные, HUD показывает результат.
- Точная цена должна разрешать покупку.
- При отказе и после завершения данные не должны самопроизвольно меняться.
