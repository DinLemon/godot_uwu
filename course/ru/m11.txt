# MODULE m11 | Управление | Клавиатура, геймпад и действия

## LESSON m11-1 | Действия и Input Map | 7
:: goals
- Что такое действие (action)
- Где настраиваются клавиши
- Какие действия уже есть

:: text Не клавиша, а действие
Можно проверять конкретную клавишу: «нажата ли D?». Но так неудобно:
- кто-то играет на стрелках, кто-то на WASD;
- кто-то на геймпаде;
- игрок захочет поменять клавиши.

Поэтому в Godot проверяют **действия** (actions). Действие — это имя, например `jump` («прыжок»). К нему привязывают клавиши: пробел, W, кнопку A на геймпаде. В коде пишешь только `jump`.

**Аналогия:** действие — это розетка, клавиши — вилки. Код подключён к розетке, а вилки можно менять.

:: text Готовые действия
В каждом новом проекте уже есть действия с приставкой `ui_`:

- `ui_left`, `ui_right`, `ui_up`, `ui_down` — стрелки;
- `ui_accept` — Enter и пробел;
- `ui_cancel` — Escape.

Они сделаны для меню, но для первых опытов подойдут. Для игры лучше завести свои: `move_left`, `move_right`, `jump`.

:: steps Создаём свои действия
- Открой **Project → Project Settings** (Проект → Настройки проекта).
- Перейди на вкладку **Input Map** (Список действий).
- В поле **Add New Action** напиши `move_left` и нажми **Add**.
- Так же добавь `move_right` и `jump`.
- Нажми **+** справа от `move_left`. Нажми на клавиатуре `A`, потом **OK**. Ещё раз **+** — и стрелку влево.
- Для `move_right` — `D` и стрелка вправо. Для `jump` — пробел и `W`.
- Закрой настройки. Всё сохраняется само.

:: quiz
Почему лучше проверять действие `jump`, а не клавишу «пробел»?
[x] Клавиши для действия можно менять, не трогая код => Верно. Плюс одно действие может работать и с клавиатуры, и с геймпада.
[ ] Клавиши нельзя проверять в Godot => Можно, но это неудобно.
[ ] Действия работают быстрее => Скорость одинаковая. Дело в удобстве.

:: recap
- **Действие** — имя (`jump`), к которому привязаны клавиши и кнопки.
- Настройка: **Project → Project Settings → Input Map**.
- Готовые: `ui_left`, `ui_right`, `ui_up`, `ui_down`, `ui_accept`, `ui_cancel`.

## LESSON m11-2 | Нажата ли кнопка | 8
:: goals
- Как проверить, зажато ли действие
- Чем «зажато» отличается от «только что нажато»

:: text Две главные проверки
- `Input.is_action_pressed("jump")` — кнопка **зажата** сейчас. Будет `true` каждый кадр, пока держишь.
- `Input.is_action_just_pressed("jump")` — кнопку **только что** нажали. `true` ровно один кадр — в момент нажатия.

Для бега — `is_action_pressed` (держишь — бежишь). Для прыжка и выстрела — `is_action_just_pressed` (одно нажатие — один прыжок).

:: text Нажатия в тренажёре
В тренажёре нет клавиатуры. Нажатия задают в строке-настройке:

```gd
# тренажёр: кадров=3 нажато=ui_right
```
— `ui_right` зажата все 3 кадра.

```gd
# тренажёр: кадров=5 нажато=jump@2
```
— `jump` нажата только на 2-м кадре. Можно и диапазон: `jump@2-4`.

Несколько действий — через запятую: `нажато=ui_right,jump@1`.

:: code
Кнопка `ui_right` зажата все кадры, `jump` нажата и держится со 2-го по 3-й кадр.
```gd
extends Node
# тренажёр: кадров=4 нажато=ui_right,jump@2-3

func _process(delta):
	var right = Input.is_action_pressed("ui_right")
	var jump_pressed = Input.is_action_pressed("jump")
	var jump_now = Input.is_action_just_pressed("jump")
	print(right, " ", jump_pressed, " ", jump_now)
```
```out
true false false
true true true
true true false
true false false
```
`just_pressed` сработал один раз — на 2-м кадре, хотя кнопку держали два кадра.

:: code
Персонаж бежит вправо, пока зажата кнопка. 4 кадра по 0.25 с, кнопка отпущена на 4-м кадре.
```gd
extends Node2D
# тренажёр: кадров=4 нажато=ui_right@1-3

var speed = 200

func _process(delta):
	if Input.is_action_pressed("ui_right"):
		position.x += speed * delta
	print(position.x)
```
```out
50.0
100.0
150.0
150.0
```

:: quiz
Игрок держит кнопку выстрела 1 секунду (60 кадров). Сколько раз сработает `is_action_just_pressed("shoot")`?
[x] 1 раз => Верно. «Только что нажата» — один кадр в момент нажатия.
[ ] 60 раз => Так было бы с `is_action_pressed`.
[ ] Ни разу => Сработает — в первый кадр нажатия.

:: recap
- `Input.is_action_pressed("x")` — зажата сейчас (каждый кадр).
- `Input.is_action_just_pressed("x")` — нажата в этот кадр (один раз).
- Бег — `pressed`, прыжок и выстрел — `just_pressed`.

## LESSON m11-3 | Оси и вектор движения | 8
:: goals
- Как получить направление одной строкой
- `get_axis` и `get_vector`

:: text get_axis — влево или вправо
Проверять «влево» и «вправо» отдельно — много кода. Есть короткий способ:

```gd
var dir = Input.get_axis("move_left", "move_right")
```

Результат:
- `-1` — зажато влево;
- `1` — зажато вправо;
- `0` — ничего или обе сразу.

Тогда движение — одна строка: `position.x += dir * speed * delta`.

:: code
Кадры 1–2: зажато вправо. Кадр 3: ничего. Кадр 4: влево.
```gd
extends Node2D
# тренажёр: кадров=4 нажато=ui_right@1-2,ui_left@4

var speed = 100

func _process(delta):
	var dir = Input.get_axis("ui_left", "ui_right")
	position.x += dir * speed * delta
	print(dir, " ", position.x)
```
```out
1.0 25.0
1.0 50.0
0.0 50.0
-1.0 25.0
```

:: text get_vector — сразу 4 стороны
Для игр с видом сверху нужны все 4 направления. `get_vector` возвращает готовый Vector2:

```gd
var dir = Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
position += dir * speed * delta
```

Порядок: влево, вправо, вверх, вниз. И сразу бонус: по диагонали длина вектора не больше 1. Персонаж не бегает быстрее по диагонали.

:: code
```gd
extends Node2D
# тренажёр: кадров=1 нажато=ui_right,ui_down

func _process(delta):
	var dir = Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
	print(dir)
	print(dir.length())
```
```out
(0.707107, 0.707107)
1.0
```
Диагональ — вектор длиной 1, а не 1.41.

:: fill
Допиши движение персонажа с видом сверху.
```gd
extends Node2D

var speed = 150

func _process(delta):
	var dir = Input.___("ui_left", "ui_right", "ui_up", "ui_down")
	position += dir * speed * ___
```
= get_vector
= delta
explain: `get_vector` даёт направление, умножение на `speed * delta` — путь за кадр.

:: recap
- `Input.get_axis("влево", "вправо")` → -1, 0 или 1.
- `Input.get_vector(лево, право, верх, низ)` → Vector2 длиной не больше 1.
- Движение: `position += dir * speed * delta`.

## LESSON m11-4 | События ввода: _input | 6
:: goals
- Второй способ ловить нажатия
- Когда он удобнее

:: text Не опрашивать, а получать события
`Input.is_action_...` — это **опрос**: каждый кадр спрашиваем «нажато?».

Второй способ — **события**. Godot сам вызывает функцию `_input(event)` при каждом нажатии, отпускании, движении мыши.

```gd
func _input(event):
	if event.is_action_pressed("jump"):
		print("Прыжок!")
	if event is InputEventMouseButton and event.pressed:
		print("Клик в ", event.position)
```

Удобно для одиночных действий: пауза, открыть меню, клик мышью.

:: code
Пауза по Escape. Код работает только в Godot: тренажёр не умеет события.
```gd
extends Node

func _input(event):
	if event.is_action_pressed("ui_cancel"):
		get_tree().paused = not get_tree().paused
		print("Пауза: ", get_tree().paused)
```
norun: yes
`get_tree().paused` — ставит всю игру на паузу. Подробнее про `get_tree()` — в модуле 14.

:: quiz
Какой способ удобнее для бега, пока зажата клавиша?
[x] `Input.is_action_pressed` в `_process` => Верно. Опрос каждый кадр — как раз для удержания.
[ ] `_input(event)` => Он срабатывает на нажатие и отпускание, но не каждый кадр, пока держишь.
[ ] Никакой — бег нельзя сделать => Можно, обычным опросом.

:: recap
- Опрос `Input.is_action_pressed` — для удержания (бег).
- `_input(event)` — Godot сам сообщает о нажатиях. Для паузы, меню, кликов.
