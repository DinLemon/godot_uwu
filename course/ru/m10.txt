# MODULE m10 | 2D: позиция и движение | Координаты, векторы и спрайты

## LESSON m10-1 | Координаты: где верх, где низ | 6
:: goals
- Как устроены координаты в 2D
- Почему y растёт вниз

:: text Точка — два числа
lab: position-sprite
visual: concept-m10
Любое место на экране — это два числа:
- **x** — сколько пикселей вправо от начала;
- **y** — сколько пикселей **вниз** от начала.

Начало (0, 0) — левый верхний угол экрана.

```tree
(0,0) ────────── x растёт вправо ──▶
  │
  │       • (200, 100)
  │
  ▼
y растёт ВНИЗ
```

!> В школе ось y смотрела вверх. В Godot (и почти во всех 2D-движках) она смотрит **вниз**. Чтобы подняться вверх, y надо **уменьшать**.

:: quiz
Персонаж стоит в (100, 300). Он прыгнул вверх. Как изменится y?
[x] Уменьшится, например до 250 => Верно. Вверх — это меньше y.
[ ] Увеличится, например до 350 => Увеличение y — это движение вниз.
[ ] Не изменится, изменится x => x отвечает за лево-право.

:: quiz
Где точка (0, 0) на экране игры (если нет камеры)?
[ ] В центре => В Godot 2D начало координат — в углу.
[x] В левом верхнем углу => Верно.
[ ] В левом нижнем углу => Так было бы, если бы y рос вверх, как в школе.

:: recap
- Позиция в 2D — пара (x, y).
- x растёт вправо, **y растёт вниз**.
- (0, 0) — левый верхний угол.

## LESSON m10-2 | Vector2 | 8
:: goals
- Что такое Vector2
- Как складывать векторы и умножать на число
- Длина и нормализация

:: text Две координаты в одной переменной
Чтобы не хранить x и y отдельно, в Godot есть тип **Vector2** — пара чисел:

```gd
var pos = Vector2(100, 50)
print(pos.x)   # 100.0
print(pos.y)   # 50.0
```

Vector2 используют для всего, у чего есть направление или место: позиция, скорость, направление взгляда, размер.

:: code
Векторы складываются по частям: x с x, y с y. На число умножается каждая часть.
```gd
extends Node

func _ready():
	var pos = Vector2(100, 50)
	var step = Vector2(10, -5)
	print(pos + step)
	print(step * 3)
	print(Vector2.RIGHT, Vector2.UP)
```
```out
(110.0, 45.0)
(30.0, -15.0)
(1.0, 0.0)(0.0, -1.0)
```
`Vector2.RIGHT` — готовый вектор «вправо на 1». Есть ещё `LEFT`, `UP`, `DOWN`, `ZERO`. Заметь: `UP` — это `(0, -1)`, потому что вверх — минус.

:: text Длина и направление
- `length()` — длина вектора (расстояние от нуля до точки).
- `normalized()` — тот же вектор, но длиной ровно 1. Это **чистое направление**.
- `distance_to(other)` — расстояние до другой точки.
- `direction_to(other)` — направление к другой точке (длиной 1).

Зачем нужна нормализация: при нажатии «вправо» и «вверх» одновременно направление `(1, -1)` длиннее, чем `(1, 0)`. Персонаж по диагонали бегал бы быстрее. `normalized()` выравнивает длину.

:: code
```gd
extends Node

func _ready():
	var v = Vector2(3, 4)
	print(v.length())
	print(v.normalized())
	var player = Vector2(0, 0)
	var coin = Vector2(30, 40)
	print(player.distance_to(coin))
	print(player.direction_to(coin))
```
```out
5.0
(0.6, 0.8)
50.0
(0.6, 0.8)
```

:: quiz
Что получится: `Vector2(2, 3) + Vector2(1, -1)`?
[x] `(3.0, 2.0)` => Верно. 2+1 = 3, 3+(−1) = 2.
[ ] `(2.0, -3.0)` => Векторы складываются по частям: x с x, y с y.
[ ] `5.0` => При сложении векторов получается вектор, а не число.

:: fill
Узнай расстояние от игрока до врага.
```gd
extends Node

func _ready():
	var player = Vector2(0, 0)
	var enemy = Vector2(6, 8)
	print(player.___(enemy))
```
= distance_to
explain: `distance_to` возвращает расстояние: здесь 10.

:: recap
- `Vector2(x, y)` — пара чисел. Части: `.x` и `.y`.
- Векторы складывают по частям, на число умножают целиком.
- `length()`, `normalized()`, `distance_to()`, `direction_to()`.
- `Vector2.UP` — это `(0, -1)`.

## LESSON m10-3 | Позиция, поворот, масштаб | 7
:: goals
- Три главных свойства Node2D
- Радианы и градусы

:: text Трансформация
У каждого `Node2D` (и его наследников: `Sprite2D`, `CharacterBody2D`…) есть три свойства:

- `position` — где стоит (Vector2);
- `rotation` — на сколько повёрнут (в **радианах**);
- `scale` — во сколько раз увеличен (Vector2, по умолчанию `(1, 1)`).

Вместе их называют **трансформацией** (transform).

:: text Радианы и градусы
Углы в Godot хранятся в **радианах**. Полный круг — это не 360, а примерно 6.28 (число `TAU`).

Привычнее думать в градусах. Варианты:
- свойство `rotation_degrees` — тот же поворот, но в градусах;
- функции `deg_to_rad(90)` и `rad_to_deg(PI)`.

```gd
rotation_degrees = 90       # повернуть на 90°
rotation = deg_to_rad(90)   # то же самое
```

:: code
```gd
extends Node2D

func _ready():
	position = Vector2(200, 150)
	scale = Vector2(2, 2)
	rotation_degrees = 180
	print(position)
	print(scale)
	print(rotation_degrees)
	scale.x = -1
	print(scale)
```
```out
(200.0, 150.0)
(2.0, 2.0)
180.0
(-1.0, 2.0)
```
`scale.x = -1` отражает узел по горизонтали — так разворачивают персонажа влево. Для спрайтов чаще используют свойство `flip_h`.

:: text Глобальная и локальная позиция
`position` — позиция **относительно родителя**. Если родитель стоит в (100, 0), а ребёнок в (10, 0), на экране ребёнок будет в (110, 0).

Позиция на экране (в мире) — это `global_position`.

:: code
```gd
extends Node2D

func _ready():
	position = Vector2(100, 0)
	var child = Node2D.new()
	add_child(child)
	child.position = Vector2(10, 5)
	print(child.position)
	print(child.global_position)
```
```out
(10.0, 5.0)
(110.0, 5.0)
```

:: quiz
Родитель в позиции (50, 50), ребёнок — `position = (0, 20)`. Какой у ребёнка `global_position`?
[ ] `(0.0, 20.0)` => Это его позиция относительно родителя.
[x] `(50.0, 70.0)` => Верно. Позицию родителя складываем с позицией ребёнка.
[ ] `(50.0, 50.0)` => Это позиция родителя.

:: recap
- `position`, `rotation`, `scale` — трансформация Node2D.
- `rotation` в радианах; `rotation_degrees` — в градусах.
- `position` — от родителя, `global_position` — в мире.

## LESSON m10-4 | Движение по направлению | 8
:: goals
- Как двигать узел по направлению с нужной скоростью
- Как двигаться к цели

:: text Формула движения
Почти всё движение в играх строится по одной формуле:

```gd
position += direction * speed * delta
```

- `direction` — куда (Vector2 длиной 1);
- `speed` — сколько пикселей в секунду;
- `delta` — сколько секунд прошло.

:: code
Пуля летит вправо-вниз со скоростью 100 пикселей в секунду. 4 кадра по 0.25 с = 1 секунда.
```gd
extends Node2D
# тренажёр: кадров=4 дельта=0.25

var direction = Vector2(3, 4).normalized()
var speed = 100

func _process(delta):
	position += direction * speed * delta
	print(position)
```
```out
(15.0, 20.0)
(30.0, 40.0)
(45.0, 60.0)
(60.0, 80.0)
```
Пуля прошла ровно 100 пикселей (по теореме Пифагора: 60² + 80² = 100²).

:: text Двигаться к цели
`move_toward(цель, шаг)` сдвигает вектор к цели, но не дальше, чем на шаг. Удобно для врагов, которые идут к игроку, и для плавных остановок.

```gd
position = position.move_toward(target, speed * delta)
```

Достигнув цели, узел останавливается сам — не проскакивает.

:: task
Монетка должна подлететь к игроку в точке `(100, 0)` со скоростью 40 пикселей в секунду. Используй `move_toward`. За 4 кадра по 1 секунде она должна дойти и остановиться:
```text
(40.0, 0.0)
(80.0, 0.0)
(100.0, 0.0)
(100.0, 0.0)
```
```gd
extends Node2D
# тренажёр: кадров=4 дельта=1

var target = Vector2(100, 0)
var speed = 40

func _process(delta):
	pass
```
```solution
extends Node2D
# тренажёр: кадров=4 дельта=1

var target = Vector2(100, 0)
var speed = 40

func _process(delta):
	position = position.move_toward(target, speed * delta)
	print(position)
```
```expect
(40.0, 0.0)
(80.0, 0.0)
(100.0, 0.0)
(100.0, 0.0)
```
hint: `position = position.move_toward(target, speed * delta)`
hint: Не забудь `print(position)` после сдвига.

:: steps Движение в Godot
visual: guide-m10-4-0
Открой `main.tscn`. В ней есть `Sprite2D` с логотипом.
- Выбери `Sprite2D` и прикрепи к нему новый скрипт (**Attach Script**). Путь: `res://logo.gd`.
- Замени текст скрипта на код ниже (кнопка «Скопировать» под ним).
- Нажми `F6`. Логотип поедет вправо и будет крутиться.

```gd
extends Sprite2D

var speed = 100

func _process(delta):
	position.x += speed * delta
	rotation += 2 * delta
```

:: recap
- Движение: `position += direction * speed * delta`.
- Направление нормализуют: `direction.normalized()`.
- `move_toward(цель, шаг)` — подойти к цели и не проскочить.

## LESSON m10-workshop | Мастерская: координаты без угадывания | 11 | practice
:: goals
- Отличить локальную позицию от положения в мире
- Проверить влияние родителя одним движением

:: text Две точки отсчёта
`position` отсчитывается от родителя. `global_position` описывает положение в общем пространстве сцены. Когда у родителя нет поворота и его масштаб равен единице, его смещение просто прибавляется к позиции ребёнка.

Пример: родитель стоит в `(100, 40)`, ребёнок в `(20, 10)`. В общих координатах ребёнок окажется в `(120, 50)`. Для повёрнутого или растянутого родителя одного сложения уже недостаточно.

:: text Попади в область
Открой [«Поставь картинку в нужную область»](#/practice/position-sprite). Сначала посмотри требуемый диапазон, затем выбери Sprite2D и меняй **Transform → Position**. После этого попробуй перетаскивание в центре.

Проверка принимает попадание в область. Не нужно угадывать единственную «правильную» координату.

:: steps Проверь систему координат в Godot
visual: workshop-m10
- Создай Node2D с именем Main и дочерний Node2D с именем Pivot.
- В Transform узла Pivot поставь Position X = 100, Y = 40. Scale оставь (1, 1), Rotation = 0.
- Добавь Sprite2D внутрь Pivot, назначь icon.svg и поставь Position X = 20, Y = 10.
- Сдвинь Pivot ещё на 50 по X. У Sprite2D локальная Position останется (20, 10), но картинка сдвинется вправо.

Ожидаемый результат: картинка движется вместе с родителем; её локальные поля сами по себе не превращаются в мировые.

:: text Ошибка, которая выглядит как телепорт
При смене родителя есть два возможных желания: сохранить место в мире или сохранить локальные значения. Они дают разный результат. В учебной [починке дерева](#/practice/repair-hierarchy) мировая позиция сохраняется, поэтому локальные числа могут измениться.

В Godot проверяй настройку сохранения глобального преобразования в диалоге Reparent и смотри на сцену после переноса.

:: quiz
При нулевом повороте и единичном масштабе родитель стоит в (100, 40), ребёнок в (20, 10). Где ребёнок в мире?
[x] (120, 50) => При этих условиях смещения складываются.
[ ] (20, 10) => Это локальная позиция относительно родителя.

:: recap
- Позиция в Inspector обычно локальная.
- Двигай родителя и наблюдай ребёнка.
- При смене родителя заранее реши, какое положение сохранить.
